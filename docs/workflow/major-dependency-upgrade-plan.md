# Major dependency upgrade plan (Ryujinx, /home/wisp/nintendont)

## Context
Minor/patch NuGet bumps are done: the build and tests pass on .NET 10 (LTS, SDK 10.0.401). Some packages were held back because the next major breaks code. The user has approved the major jumps. This file is written so several agents can each take one workstream.

Central versions live in `Directory.Packages.props`. Do not edit versions in individual csproj files.

## Ground rules for every agent
- Work on a branch per workstream (`upgrade/<name>`). Merge in the order below.
- After each workstream run `dotnet build Ryujinx.sln -c Release`, `dotnet test Ryujinx.sln -c Release` and `dotnet format --verify-no-changes`. Baseline: 30,629 tests passed, 0 failed.
- Do not weaken or skip tests. Do not hand-edit `Autogenerated/` files.
- Follow `CLAUDE.md`, `AGENTS.md` and `docs/coding-guidelines/coding-style.md`.
- If a package has no compatible release, stop and report. Do not pin a hack.
- Do not touch net target frameworks. .NET 11 is RC only (GA Nov 2026) and is out of scope.

## Workstreams

### A. Test stack: NUnit 3.14 → 4.6 (independent, do first)
- Scope: `src/Ryujinx.Tests`, `Ryujinx.Tests.Memory`, `Ryujinx.Tests.Unicorn` (62 files use classic asserts).
- NUnit 4 removes the classic model: about 271 `Assert.AreEqual`, 143 `IsTrue`, 104 `IsFalse`, plus `Assert.True`/`Assert.False`. Convert them to the constraint model `Assert.That(..., Is.EqualTo(...))` / `Is.True` / `Is.False`. This can be scripted, or use the `NUnit.Analyzers` code fixes (NUnit2005, NUnit2004, NUnit2003 and similar).
- Keep `[Values]` (about 2,500), `[Random]`, `[Range]` and `[TestCase]` semantics unchanged. Check the test count stays the same after conversion.
- Bump `NUnit` to 4.6.1 and `NUnit3TestAdapter` to 6.3.0 (`Microsoft.NET.Test.Sdk` is already 18.x).
- Done when the same tests pass, with the skipped count unchanged (133 before).

### B. Roslyn generators: Microsoft.CodeAnalysis 4.8 → 5.9 (independent)
- Projects: `Ryujinx.HLE.Generators`, `Ryujinx.Horizon.Generators`, `Ryujinx.Horizon.Kernel.Generators`, `Ryujinx.UI.LocaleGenerator`.
- Bump `Microsoft.CodeAnalysis.CSharp` and `.Analyzers` to 5.9.0.
- Verify the generators still target netstandard2.0 and load in the SDK 10 compiler. Confirm generated output is unchanged: diff the `obj/` generated files before and after.
- Watch for incremental-generator API deprecations.

### C. Tmds.DBus.Protocol 0.21 → latest (small, after D)
- Used in 1 file (find with `grep -rl Tmds.DBus src`). Avalonia pins a version, so do this after D. It may need to follow Avalonia's own dependency.
- Only bump if it is compatible with the chosen Avalonia. Otherwise leave it.

### D. UI stack (largest, one agent, sequential)
Order matters. Do not mix these in one commit.
1. **SkiaSharp 2.88.9 → 3.x/4.x**. It must match the version Avalonia requires. Check the Avalonia 12 release notes for its Skia version first.
   - 13 files use SkiaSharp: `Ryujinx/AppHost.cs`, `Ryujinx/Program.cs`, `Ryujinx.HLE/.../SoftwareKeyboardRendererBase.cs`, `CaptureManager.cs`, `UI.Common/Helper/ShortcutHelper.cs`, `Ryujinx.Gtk3` windows.
   - HLE and Gtk3 use it for image and bitmap work. Expect API changes (`SKImageInfo`, `SKFilterQuality` → `SKSamplingOptions`, `SKBitmap` constructors).
2. **Avalonia 11.3 → 12.1.2** (`Avalonia`, `.Desktop`, `.Controls.DataGrid`, `.Markup.Xaml.Loader`, `.Diagnostics`). Diagnostics has no 12.x, so use the 12-compatible replacement/dev-tools package.
   - Read the official Avalonia 11→12 breaking-changes guide first.
   - Areas: `src/Ryujinx/UI/**` (Views, Windows, Controls, Renderer, Applet) and `.axaml` files. The renderer is the risky part: `UI/Renderer` embeds native GL/Vulkan surfaces.
3. **FluentAvaloniaUI 2.0.5 → 3.1.0**. It is used in 45 files (ContentDialog, NavigationView, `FAIcon` etc.). It must be a version that supports the chosen Avalonia. Expect renamed controls and styles.
4. **Avalonia.Svg / Avalonia.Svg.Skia** (5 files) to the release matching Avalonia 12.
5. **DynamicData** (5 files) to the latest 9.x if Avalonia 12/ReactiveUI requires a specific version.
- Smoke test each step by launching with `./scripts/run-debug.sh` and checking: the main window, the Settings window, the game list (grid and list), and the theme switch (recent commit added themes). Also open a ContentDialog (for example About or Amiibo) and check the log for binding errors.

### E. Docs and CI
- Update `CLAUDE.md`/`AGENTS.md` if commands change. Check `.github/workflows` and `flake.nix` for pinned versions.
- Nix: if Avalonia 12 or SkiaSharp 4 needs new native libs, list them for the user to add to their Nix config. Do not edit the user's system config.

## Order and parallelism
A and B run in parallel with D. C follows D. E goes last. Merge order: A, B, D, C, E. Each merge must leave main green.

## Verification (end to end)
1. `dotnet restore Ryujinx.sln && dotnet build Ryujinx.sln -c Release` gives 0 errors and no NU16xx warnings.
2. `dotnet test Ryujinx.sln -c Release` gives no failures and the same test count as the baseline.
3. `dotnet format --verify-no-changes` is clean, matching CI.
4. `dotnet list package --outdated` shows only intentionally held packages.
5. Run `./scripts/run-debug.sh` and check the UI smoke list from D, plus a clean startup log.
6. If a game or homebrew is available, boot it once to confirm the renderer and software keyboard capture still work.

## Risks
- Avalonia 12 plus FluentAvalonia 3 is the likeliest source of days of work. If it stalls, ship A and B and keep the UI on 11.3.
- SkiaSharp 4 may be incompatible with the Gtk3 frontend. Decide whether Gtk3 stays supported.
