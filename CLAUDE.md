# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Ryujinx: an open-source Nintendo Switch emulator in C# (.NET 10, SDK pinned in `global.json`). Solution: `Ryujinx.sln`; all projects live under `src/`. NuGet versions are centrally managed in `Directory.Packages.props`. See `AGENTS.md` for the contributor guidelines summarized below.

## Commands

- `nix develop` — pinned shell with .NET SDK and Linux runtime libs (`nix develop path:.` for an uncommitted flake).
- `dotnet restore Ryujinx.sln`
- `dotnet build Ryujinx.sln -c Release -o build`
- `dotnet test Ryujinx.sln -c Release`
- Single project / test: `dotnet test src/Ryujinx.Tests -c Release --filter "FullyQualifiedName~TreeDictionaryTests"`
- `dotnet format` — CI (`.github/workflows/checks.yml`) runs `dotnet format whitespace|style|analyzers --verify-no-changes`; run it before a PR.
- `./scripts/run-debug.sh [args]` — launches the GUI through the Nix shell.

## Architecture

The emulator is split into many small projects under `src/`; the flow is roughly:

- **Frontends**: `Ryujinx` (Avalonia GUI), `Ryujinx.Gtk3`, `Ryujinx.Headless.SDL2`; shared UI logic in `Ryujinx.UI.Common`.
- **`Ryujinx.HLE`**: high-level emulation of the Switch OS — the kernel (`HOS/Kernel`), system services (`HOS/Services`, IPC interfaces such as `IHidServer`), loaders and filesystem. The `Device` class ties CPU, GPU, audio and input together.
- **`Ryujinx.Horizon` / `Horizon.Common`**: newer user-mode service implementations (sysmodules) reimplemented outside HLE, with source generators for IPC (`Ryujinx.Horizon.Generators`, `Horizon.Kernel.Generators`, `Ryujinx.HLE.Generators`).
- **CPU**: `Ryujinx.Cpu` (execution engines/memory tracking) on top of `ARMeilleure` (ARM JIT compiler) and `Ryujinx.Memory` (virtual memory manager).
- **GPU**: `Ryujinx.Graphics.Gpu` emulates the Maxwell GPU and talks to a backend through the abstraction in `Ryujinx.Graphics.GAL`; backends are `Graphics.Vulkan` and `Graphics.OpenGL`. Supporting projects: `Graphics.Shader` (Maxwell shader → IR → GLSL/SPIR-V, using `Spv.Generator`), `Graphics.Texture`, `Graphics.Device`, `Host1x`, `Nvdec*`/`Vic`/`Video` (video decoding).
- **Audio**: `Ryujinx.Audio` (renderer + `Integration`/`Backends/CompatLayer`) with pluggable backends `Audio.Backends.{SDL2,OpenAL,SoundIo}`.
- **Input**: `Ryujinx.Input` (abstraction) and `Ryujinx.Input.SDL2`; `Ryujinx.SDL2.Common` is shared SDL setup.
- **Tests**: NUnit in `Ryujinx.Tests`, `Ryujinx.Tests.Memory`, `Ryujinx.Tests.Unicorn` (compares the CPU against Unicorn).
- Packaging assets in `distribution/`; localization via Crowdin (`crowdin.yml`, `Ryujinx.UI.LocaleGenerator`).

## Conventions

- Style: `docs/coding-guidelines/coding-style.md` and `.editorconfig` — 4 spaces (2 for md/json/yml/props/csproj), Allman braces, explicit visibility, `_camelCase` private fields, `s_` static fields, `using` outside namespaces, language keywords (`int`, `string`).
- Don't hand-edit files in `Autogenerated/` directories.
- Prefer the existing file's style over the general guidelines; no style-only PRs; don't touch licensing files/headers.
- Commits: concise imperative subject (≤50 chars), body wrapped at 72, `Fix #123` when applicable.
- Add NUnit tests next to the relevant subsystem, named `*Tests`; don't weaken or skip failing tests.
